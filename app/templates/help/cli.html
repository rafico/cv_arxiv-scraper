CLI Commands

The web UI is enough for most users. Use the CLI if you want automation, historical backfills, headless operation, or shell scripting.

After installing with pip install -e ., these commands are available globally:

Command Description
cv-arxiv-scrape Run one scrape from the terminal and print matched papers
cv-arxiv-digest Build or send the email digest. Useful flags: --dry-run, --send-only
cv-arxiv-sync Historical sync for backfilling older papers. Flags: --from, --to, --category, --chunk-days. Or --query + --collection (optional --max-results, default 1000) to import an arXiv search into a collection
cv-arxiv-backfill Run enrichment backfills on papers already in your database
cv-arxiv-mcp Serve your corpus to Claude Desktop as an MCP backend (see below). Needs pip install '.[mcp]'

Standalone scripts (python scrape_cli.py, python export_cli.py, etc.) also work without installing the package.

MCP Server (Claude Desktop)

Expose your personalized, ranked, full-text-indexed corpus to Claude Desktop (or any Model Context Protocol client) as a backend, so the assistant searches and reads your papers instead of the open web.

Install the optional extra, then add cv-arxiv-mcp to your claude_desktop_config.json (Claude Desktop → Settings → Developer → Edit Config):

pip install '.[mcp]'

# claude_desktop_config.json
{
  "mcpServers": {
    "cv-arxiv": {
      "command": "cv-arxiv-mcp",
      "env": { "CV_ARXIV_DATA_DIR": "/path/to/cv_arxiv-scraper/instance" }
    }
  }
}

Point CV_ARXIV_DATA_DIR at the directory holding your database, FAISS index, and config.yaml: a source checkout's absolute instance/ path, or ~/.local/share/cv-arxiv for a default cv-arxiv serve. A path with no database silently starts a fresh, empty corpus. Restart Claude Desktop and the tools appear: search_papers, get_paper, get_summary, top_ranked_today, list_collections, get_collection, get_paper_text, ask_paper, whats_new, and the write tools set_decision, tag_papers and add_to_collection. The mcp package is optional — the app and web server run without it.

whats_new lists the papers that arrived in the last few days (seven by default), are in no collection yet and score close to one. They are candidates to screen, not recommendations: the collection each is attributed to is wrong about one time in five. get_collection can filter by tag, decision and added_since_days.

The write tools are for sessions you attend. set_decision records include, maybe or exclude for one paper in a collection, with a one-line reason, and files the paper if it is not in the collection yet; it never overwrites a decision you made. tag_papers adds one tag to up to 50 papers and never removes one. add_to_collection files a paper; an unknown collection name is an error unless create is set. What the assistant decided or added shows on the collection page with an Agent mark until you confirm it, and every write is appended to mcp_writes.jsonl next to the database. Add "args": ["--read-only"] to the config to register none of the write tools, for example for an unattended run. Such a server does not run the built-in scrape scheduler either.

Enrichment Backfills

Use these when papers were added before a feature was enabled, or when you want to rebuild missing metadata later.

Subcommand What it does
embeddingsBackfill missing SPECTER2 embeddings
index-rebuildRebuild the full FAISS index from the database
citationsFetch citation counts from Semantic Scholar
citation-edgesFetch reference lists (OpenAlex + Semantic Scholar) and build the citation graph edges for papers added before the graph existed
openalexFetch OpenAlex metadata (topics, OA status)
thumbnailsGenerate PDF first-page thumbnails
allRun all of the above

All subcommands accept --batch-size N and --delay SECONDS.

Scheduled Scrapes

The app can scrape (and optionally email the digest) automatically at a set time each day, without needing cron. Configure it under Settings → Automation → Scheduling, or directly in config.yaml:

scheduler:
  enabled: true
  daily_at: "08:00"    # 24-hour format, UTC
  send_digest: true    # email the digest after each scheduled scrape

Prefer external automation (server not always running)? Point cron or a systemd timer at the installed console scripts:

0 8 * * * cv-arxiv-scrape && cv-arxiv-digest

When arXiv Refuses Requests

A log line or error saying arXiv refused a request (HTTP 406, or 429) means arXiv’s export API is throttling your host; waiting a few minutes doesn’t clear it. The app stops asking for 30 minutes and falls back on its own:

  • Scrapes, cv-arxiv-sync date ranges and id lookups use arXiv OAI-PMH. Id lookups run at about one per second, and a seed import resolves 25 new ids per request, so run it again for the rest.
  • cv-arxiv-sync --query uses Semantic Scholar search instead. It covers Computer Science only, so a non-cs --category or a query made only of cat: terms is refused.
  • A cv-arxiv-sync range reaching far back fails instead of leaving a gap; run it again once arXiv accepts requests.

Multiple Feed Sources

Monitor additional arXiv categories or custom RSS feeds beyond cs.CV. Add, remove, and toggle feed sources under Settings → Research Setup → Feed Sources (pick an arXiv category or paste a custom RSS URL), or via the /api/feed-sources API.

AI Summaries (LLM)

Optional feature

The app works fine without AI. Summaries and topic tags are generated extractively by default. Enabling LLM adds richer summaries and an AI relevance score.

When enabled, the LLM reads each paper’s title and abstract to produce:

  • A plain-language TL;DR summary describing what the paper does and why it matters (shown on each paper card in the dashboard)
  • A relevance score (0–10) relative to your research interests

Without LLM, the app still generates an extractive summary from the abstract. You can control how many lines of the summary are visible on paper cards via Settings → Ranking → Summary lines.

Setup

1

Enable in Settings

Go to Settings → LLM / AI and toggle LLM on.

2

Choose a provider

Supported providers: OpenRouter for a hosted model, or Ollama for a local model. Add the API key or local base URL.

3

Run a scrape

AI summaries and relevance scores are generated during the scrape. Papers already in the database are not automatically re-processed unless you run a backfill workflow.

config.yaml example

llm:
  enabled: true
  provider: openrouter         # or "ollama"
  model: google/gemma-4-31b-it:free
  # base_url: http://localhost:11434/v1   # for Ollama
  max_concurrent: 4
